# Задание к лекции 5

Модуль учёта времени для системы управления задачами.

Задание к лекции 5 «Этапы разработки программного продукта».
Python 3.10 или новее, только стандартная библиотека. Работает в Windows, Linux и macOS.

## Возможности

- Запуск и остановка таймера конкретной задачи.
- Суммирование нескольких сеансов, включая текущий активный сеанс.
- Отчёты по всем задачам или одной задаче: текст, JSON и CSV.
- Интеграция с `TaskManager`, `Task`, `User`, `Priority`, `Status` из модели лекции.
- Создание задач и пользователей, назначение исполнителей, изменение статусов.
- Сохранение задач и таймеров в SQLite между запусками программы.

## Быстрый запуск

Откройте терминал в каталоге проекта. Установка сторонних пакетов не нужна.
В Windows вместо `python` можно использовать `py -3`.

```sh
python main.py user "Иван Петров" ivan@example.com
python main.py task "Разработать модуль учёта времени" --description "Задание к лекции 5" --priority HIGH --due 2026-12-31
python main.py assign 1 1
python main.py start 1
```

Поработайте над задачей, затем выполните:

```sh
python main.py stop 1
python main.py report
python main.py report --task 1 --format json
python main.py report --format csv --output report.csv
python main.py status 1 DONE
python main.py list
```

Пример предполагает новую базу данных. Идентификаторы выводятся при создании.
Повторите `start 1` и `stop 1`, чтобы добавить следующий сеанс.
`python main.py --help` показывает все команды; `python main.py task --help` — параметры задачи.
По умолчанию данные находятся в `tasks.db` в текущем каталоге.
Другой файл задаётся **перед командой**: `python main.py --db my_tasks.db report`.
CSV сохраняется с UTF-8 BOM для корректного открытия кириллицы в Excel.

## Использование как модуля

```python
from datetime import datetime, timedelta
from system_design import Priority
from task_manager import TaskManager
from time_tracker import TimeTracker

with TaskManager("tasks.db") as manager:
    user = manager.create_user("Мария", "maria@example.com")
    task = manager.create_task(
        "Подготовить отчёт", "Отчёт по проекту", Priority.MEDIUM,
        datetime.now() + timedelta(days=7),
    )
    manager.assign_task(task.task_id, user.user_id)
    tracker = TimeTracker(manager)
    tracker.start_timer(task.task_id)
    # Выполнение работы...
    seconds = tracker.stop_timer(task.task_id)
    print(seconds, tracker.get_total_time(task.task_id))
    print(tracker.generate_report())
```

Интеграция сохраняет сигнатуры основных методов лекционного менеджера, но заменяет
словари на SQLite. Модели — неизменяемые снимки: после изменения перечитывайте задачу
через `get_task()`. Статус меняется через `manager.update_status()`, назначение —
через `manager.assign_task()`. Время хранится отдельно, с внешним ключом на задачу.

## Проверка

```sh
python -m unittest discover -s tests -v
```

Тесты проверяют точные длительности с управляемыми часами без ожидания: повторные сеансы,
активные таймеры, независимые задачи, неизвестные ID, двойной старт/стоп, перевод часов,
часовые пояса, сохранение после перезапуска, два подключения к базе, назначение,
статусы, форматы отчётов и полный сценарий CLI. GitHub Actions запускает их на Python 3.10–3.13.

## Правила учёта

Одна задача может иметь только один активный таймер; ограничение обеспечивается самой БД.
Разные задачи могут работать параллельно, поэтому общий итог — сумма человеко-секунд
по задачам, а не длительность календарного промежутка. Времена сохраняются в UTC,
длительности — в секундах с дробной частью. Каждый отчёт использует единый момент времени.
Отчёт не останавливает таймеры. Задачи без сеансов имеют нулевое время.

Таймер продолжает учитывать календарное время после закрытия терминала или перезагрузки.
Приостановка компьютера также входит в интервал. Завершение задачи не останавливает
таймер автоматически: выполните `stop` отдельно. Перевод системных часов может влиять
на длительность; отрицательные интервалы отклоняются с понятной ошибкой.
Границы отчёта — все сохранённые сеансы выбранных задач; фильтрации по датам нет.

## Структура и этапы разработки

| Этап | Результат |
| --- | --- |
| Анализ требований | Четыре требования задания перечислены в разделе возможностей |
| Проектирование | Модели в `system_design.py`, схема SQLite в `task_manager.py` и `time_tracker.py` |
| Реализация | `TaskManager` хранит задачи; `TimeTracker` управляет интервалами; `main.py` предоставляет CLI |
| Тестирование | `tests/test_time_tracker.py`, автоматическая проверка в GitHub Actions |
| Внедрение | Клонировать репозиторий, установить Python 3.10+, запустить команды выше |
| Сопровождение | Резервная копия `tasks.db` при закрытой программе, исправления через Git |

Решение предназначено для локального учебного использования. Аутентификация,
сетевой сервер и многопользовательский веб-интерфейс не входят в объём задания.
Исходные учебные материалы не включены в репозиторий.
